# Knowledge Compilation Contract

## Purpose

Knowledge Compilation 将一套完整长课程的可追溯 Evidence 编译为结构化、长期可复用的候选 Markdown 知识资产。该过程由高理解模型辅助执行，由人工审批；它不是本地 Python 算法，也不是无人监督的一键总结。

## Input Contract

允许输入：

- 课程 TXT Transcript；
- 对应 SRT 和时间戳；
- `manifest.json`；
- 用户明确提供的课程元信息；
- 本 Contract、标准 Prompt 和输出 Template。

默认禁止联网补充或使用模型记忆修正课程观点。若任务明确允许外部核验，外部资料必须单独标注，不能伪装成课程内容。

## Evidence Contract

1. 不得把模型已有知识伪装成课程内容。
2. 不得补写 Transcript 中不存在的事实、原因或结论。
3. 应区分明确课程内容、讲师观点、课程示例、学员推测、模型推断和无法确认内容。
4. 关键结论、重要案例、争议和不确定项应尽量回指稳定来源编号与时间戳，如 `[F2 01:23:45]`。
5. 品牌、标准号、产品型号、单位、精确数字和异常专业表述缺乏充分证据时必须标记 `[待确认]`。
6. 讲师明确不了解、无法回答或表示有争议的内容，应保留为课程能力边界。

## Compilation Contract

1. 先读取完整课程，再设计最终章节；禁止逐文件总结后机械拼接。
2. 按语义重建课程，而不是按文件名、录音数量或日期制造章节。
3. 删除寒暄、连线确认和无知识增量的口头重复。
4. 合并切片重复，但保留讲师重述中新增加的条件、例外、案例和推导。
5. 保留关键上下文、适用条件、限制、反例、失效场景和课程能力边界。
6. 不为追求简短而删除限制条件，不为追求流畅而改变原意。
7. 集中答疑应归入对应知识主题；不能确认的问答进入待确认或能力边界。
8. 建立稳定来源编号映射，记录真实文件名、时长、主要主题和边界判断。

## Boundary Rules

相邻文件至少区分：确认重复、疑似重复、直接接续和正常转场。只有句序、例子、数字和时间关系足以证明相同录音时才删除重复；证据不足时保守处理并记录疑点。

## Output Contract

默认只输出一个候选文件：

```text
Course_Knowledge.md
```

其职责包括：

- 状态标识（候选或人工已批准）；
- 课程概览、范围和适用对象；
- 知识地图；
- 按语义重建的主体内容；
- 原理、方法、条件、限制、案例和易错点；
- 待确认项和课程能力边界；
- 稳定来源索引与关键来源引用；
- 编译和人工审阅记录。

结构可按课程实际内容调整，不应为了填满模板制造知识。

## Uncertainty Contract

统一使用 `[待确认]`，适用于：

- Transcript 含糊或疑似转录错误；
- 术语、数字、单位、品牌、标准号或型号无法由课程内证据确认；
- 文件顺序、重复边界或上下文不完整；
- 课程内部存在矛盾；
- 模型只能推断而不能直接从 Evidence 支持。

不得用“可能正确”的流畅文本隐藏不确定性。人工审阅完成前不得移除标记。

## Completion Gate

模型完成后必须停止并等待人工审阅。只有通过 [Human Review](Human_Review.md) 后，候选文档才可升级为最终 Knowledge Asset。
